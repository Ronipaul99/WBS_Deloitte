# Step 4 decisions before implementation

The initial checkout has Step 1 submission coordination and Step 2 workflow binding but no structured review storage or import lease/identity. DocumentSummary already has an authoritative revision and a unique document row. Submission leases are constrained to SUBMITTING and cannot safely represent local import ownership. A separate request-scoped import record, nullable structured content/source-request columns on DocumentSummary, and scoped constraints require one additive migration from the actual head e94b7d20a631. Historical migrations remain unchanged.

Policy: strict seven-category external-summary-v1; exact Unicode substring quotes and checked canonical chunk hashes, without whitespace/case normalization. Ingestion records physical chunk page sets but does not map quote offsets to pages. Require citations to carry the entire canonical chunk page set; reject narrower/invented page precision, undocumented quote normalization and missing page provenance. This establishes chunk-page coverage, not exact quote-page attribution. Preserve original result, null confidence and warnings. Reject sections over their advertised edit limit, total result over configured byte bounds, and compatibility projection over 50,000 characters. No generated key points or requirements are inferred. Replacement is limited to unapproved, expected-revision summaries with no existing requirements register.

Import lease, attempts, first-completion/grace clock, outcome, digest and immutable imported identity live in summary_result_imports, not remote Jobs or submission execution fields. Short transactions follow document -> workflow -> import record -> job shared lock -> summary/bindings. Validation occurs between claim and fenced acceptance; acceptance rechecks result/canonical digests, scope, authorization, lifecycle and revision. No transaction spans broker/network I/O.

Final locking detail: Step 2 admission obtains the document/workflow guard, then the request is refreshed under a write lock, followed by import ownership, exact job shared lock, summary and matching associations. Existing legacy edits/approval now take the same document guard even with workflow recovery disabled. A queued legacy summary worker also takes that guard and refuses to overwrite an externally sourced draft. These are necessary protections of the new import boundary; no general worker/job redesign is included.

Current Step 3 rejects IMPORTED metadata and has no structured review renderer. Step 4 exposes truthful persisted import/read contracts but keeps workflow recovery on checkpoint and blocks legacy structured-summary mutations, approval and downstream generation. No frontend changes; Step 5 owns that handoff. Existing legacy summaries remain readable and editable.

All qualification remains synthetic/local unless separately evidenced. No application database, upstream service or VM access is authorized.
